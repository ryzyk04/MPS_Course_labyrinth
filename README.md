# Лабиринт — Arduino Uno

Прошивка модуля «Лабиринт» на светодиодной матрице 8 × 8 с MAX7219. В памяти записаны 27 лабиринтов: по девять для лёгкой, средней и сложной сложности.

блаблабла - сережа

**Временное решение: общая шина UART/I²C.** Параметры приходят с ESP32 через Uno «Провода». Адрес лабиринта — **0x12**. Полная схема и протокол — в [docs/bus.md](docs/bus.md).

## Подключение

| Элемент | Подключение |
|---|---|
| Матрица MAX7219, VCC | 5V |
| Матрица MAX7219, GND | Общий GND с Arduino |
| Матрица MAX7219, DIN | D11 |
| Матрица MAX7219, CS / LOAD | D10 |
| Матрица MAX7219, CLK | D13 |
| Кнопка «Вверх» | D2 → кнопка → GND |
| Кнопка «Вниз» | D3 → кнопка → GND |
| Кнопка «Влево» | D4 → кнопка → GND |
| Кнопка «Вправо» | D5 → кнопка → GND |
| Индикатор лёгкого уровня | D6 → резистор 220–330 Ом → анод светодиода; катод → GND |
| Индикатор среднего уровня | D7 → резистор 220–330 Ом → анод светодиода; катод → GND |
| Индикатор сложного уровня | D8 → резистор 220–330 Ом → анод светодиода; катод → GND |
| Индикатор столкновения со стеной | D12 → резистор 220–330 Ом → анод светодиода; катод → GND |
| I²C SDA | A4 → A4 wires и A4 simon |
| I²C SCL | A5 → A5 wires и A5 simon |

Кнопки используют `INPUT_PULLUP`: отпущенная кнопка даёт `HIGH`, нажатая замыкает вход на GND и даёт `LOW`. Внешние подтягивающие резисторы не требуются. У каждого отдельного светодиода должен быть свой последовательный резистор.

Сигнальные контакты подключаются к входу модуля матрицы, обозначенному DIN. Управление MAX7219 реализовано непосредственно в прошивке через `shiftOut()`.

## Настройки и запуск

Настройки находятся в `src/main.cpp`:

- `BRIGHTNESS = 4` — яркость матрицы MAX7219, от 0 до 15. Значение 0 соответствует минимальной яркости, а не выключению.
- `ALERT_MS = 100` — длительность включения индикатора D12 после столкновения, в миллисекундах.
- `SHOW_FINISH = true` — показывать мигающий финиш и проверять победу. При `false` финиш скрыт и переход к следующему лабиринту при достижении финиша отключён.
- `REPEAT_DELAY_MS = 250` — задержка перед началом повторных ходов при удержании кнопки.
- `REPEAT_RATE_MS = 150` — интервал между повторными ходами при удержании.
- `PIN_DIN`, `PIN_CS`, `PIN_CLK`, `PIN_UP`, `PIN_DOWN`, `PIN_LEFT`, `PIN_RIGHT` и `PIN_LED_*` — распиновка модуля.

После изменения настроек нужно собрать и загрузить прошивку заново.

При включении Uno настраивает матрицу и ждёт команду I²C, игровая индикация выключена. В веб-пульте отправьте сид и сложность через подготовку задания «Провода», затем нажмите D21 на ESP32. Шлюз передаст параметры всем трём головоломкам. После команды загорается индикатор сложности, игрок устанавливается на старт.

Выбор схемы воспроизводим: индекс `difficulty * 9 + seed % 9`, где difficulty — 0/1/2. Старт и финиш берутся из записи `LEVELS`. Повтор пакета с тем же ID раунда не сбрасывает позицию и ошибки; новое нажатие D21 создаёт новый ID и начинает задание заново. Прямой UART с ESP32 не используется: D0/D1 остаются для USB Serial. Общие SDA/SCL подтянуть двумя резисторами 4,7 кОм к 5V на wires, земли всех плат объединить. I²C к ESP32 напрямую не подключать.

## Игровое поле и уровни сложности

| Сложность | Размер поля | Количество лабиринтов | Индикатор |
|---|---|---|---|
| Лёгкая | 4 × 4 | 9 | D6 |
| Средняя | 6 × 6 | 9 | D7 |
| Сложная | 8 × 8 | 9 | D8 |

Поле располагается от левого нижнего угла матрицы. На лёгком и среднем уровнях клетки за пределами поля не используются. Координата `(0, 0)` соответствует левому нижнему углу; `x` растёт вправо, `y` — вверх.

Точка игрока горит постоянно. Финиш мигает: 300 мс включён, 300 мс выключен. Стены на матрице не показываются. По исходному положению игрока и финиша можно найти нужную схему в разделе «Лабиринт» руководства по обезвреживанию. Определять схему следует до первого хода.

Если изображение на физической матрице повёрнуто относительно кнопок, проверьте ориентацию модуля: прошивка считает строку 0 верхней, столбец 0 — левым. Преобразование координат в светодиоды находится в `draw()`.

## Кнопки и решение

Нажатие кнопки сразу делает один ход в выбранном направлении. При удержании включается автоповтор с задержками `REPEAT_DELAY_MS` и `REPEAT_RATE_MS`. Если зажато несколько кнопок, обрабатывается первая в порядке: вверх → вниз → влево → вправо. Отдельный антидребезг в текущем коде не реализован.

При попытке пройти сквозь стену или выйти за границу поля игрок остаётся на месте, а индикатор D12 включается на 100 мс. Это малая ошибка: решение можно продолжать, лабиринт и позиция не сбрасываются. Счётчик ошибок передаётся шлюзу по I²C, мастер назначает штраф однократно за каждую новую ошибку.

Когда игрок достигает финиша, вся матрица четыре раза включается на 200 мс и выключается на 200 мс, затем остаётся включённой. Модуль сообщает SOLVED, движения прекращаются до новой команды. Анимация не блокирует I²C и может быть прервана новым заданием. Автоматического перехода к следующей схеме нет.

Нажатие Reset возвращает ожидание команды. Если шлюз продолжает текущий раунд, он обнаружит сброс и повторно передаст задание; прогресс этой Uno будет потерян.

## Данные лабиринтов и монитор порта

Схемы заданы массивами `WALLS_EASY_1`–`WALLS_EASY_9`, `WALLS_MEDIUM_1`–`WALLS_MEDIUM_9` и `WALLS_HARD_1`–`WALLS_HARD_9`. Каждая запись `{x1, y1, x2, y2}` описывает стену между двумя соседними клетками. Стена запрещает движение в обе стороны; границы поля проверяются отдельно.

Таблица `LEVELS` хранит размер поля, сложность, координаты старта и финиша и ссылку на массив стен. Схемы и таблица находятся во флеш-памяти (`PROGMEM`), в оперативную память копируется описание текущего уровня. При изменении схем нужно согласованно обновлять стены и запись в `LEVELS`.

USB-монитор работает на **9600 бод**, кодировка — UTF-8. При выборе лабиринта выводится сложность текстом, после обработки кнопки — текущие координаты вида `x=2 y=1`. Вывод номера лабиринта в `pickLevel()` закомментирован; для отладки его можно включить. Этот номер будет общим индексом 1–27.

## Сборка и проверка

Из папки проекта:

```powershell
pio run
pio run -t upload
pio device monitor
```

В `platformio.ini` выбраны `atmelavr`, плата `uno` и фреймворк `arduino`. Параметры `upload_port` и `monitor_port` пока не заданы. Если одновременно подключено несколько плат, найдите нужный COM-порт через `pio device list` и укажите его в секции `[env:uno]` для загрузки и монитора.

Проверка логики без платы: `python test/check_bus.py` (нужен `g++` в PATH). Проверяются все 27 схем и пути до финиша, счётчик ошибок, повторные команды и сохранение победы. На плате проверьте ожидание задания, приём общего сида/сложности, четыре направления, автоповтор, вспышку D12 при столкновении и передачу ошибки мастеру, затем победу и ожидание новой команды.
